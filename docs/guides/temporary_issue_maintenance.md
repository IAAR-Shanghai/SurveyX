# 暫存問題紀錄維護指引

本文件說明如何建立、更新與結案 `docs/temporary_issues/` 內的暫存問題紀錄，確保代理交接與歷史追蹤一致。

## 1. 建立時機與命名

- 當協作進度需暫停、依賴其他工作或尚未解決時，立即建立暫存紀錄。
- 檔名格式：`YYYYMMDD_<簡短主題>.md`（例：`20250318_pdf_spacing_glitch.md`）。
- 內容建議模板：

```markdown
# <議題簡述>

## 背景
- 問題來源與觸發情境
- 涉及的模組 / 任務 / 輸出路徑

## 目前狀態（YYYY-MM-DD HH:MM +TZ）
- 已完成的步驟
- 尚未解決的症狀
- 需要等待的條件或資源

## 已嘗試的作法
- 指令、程式碼片段或檢查項目
- 觀察到的輸出（若內容長，請提供路徑）

## 待辦事項
- 下一步建議（按優先順序）
- 需詢問使用者或其他代理的問題
```

## 2. 更新紀錄

- 新進展請以時間戳記段落追加（例：`## 2025-03-19 15:20 +08`），說明操作、結果與對應檔案。
- 若需附長篇分析，請將詳細內容寫至 `docs/qa-notes/` 中的對應主題，再於暫存檔連結。
- 交接時務必確認「下一步」「已知風險」「待確認事項」是否清楚列出，並在對話回報中附上檔案路徑。

## 3. 結案流程

當問題解決或不再需要追蹤時：

1. 於檔案末段新增「## 結案紀錄」：
   - 解決方案與關鍵指令／程式碼／輸出位置
   - 後續監控或建議驗證步驟
   - 是否已更新相關正式文件（例如 `docs/qa-notes/`、`pipeline&modules.md`）

2. **歸檔至 `docs/resolved_issues/`**（推薦）：
   - **建立或使用主題目錄**：`mkdir -p docs/resolved_issues/<主題>/archive`
   - **移動文件**：將相關檔案從 `temporary_issues/` 移至主題目錄
   - **建立 README**：在主題目錄建立或更新 README.md 作為總覽
   - **更新索引**：
     - 在 `docs/resolved_issues/README.md` 新增該主題條目
     - 從 `docs/temporary_issues/README.md` 移除該問題
   - **說明歸檔**：在回報中標註歸檔路徑與結案理由

3. 其他處理方式（視情況選用）：
   - **整合至正式文件**：若內容適合長期參考，整合至 `docs/qa-notes/<主題>.md`
   - **清理**：若內容純屬臨時資訊且已無參考價值，可刪除檔案，但須在回報中說明刪除原因與結案時間

## 4. 常見注意事項

- 保持簡潔但可追蹤：優先提供「可重現資訊」與檔案路徑，避免貼上長輸出。
- 若議題會持續追蹤（需觀察或等待資源），可將狀態標註為「待觀察」，定期回顧是否仍需保留。
- **問題解決後應立即歸檔**：`docs/temporary_issues/` 僅存放尚未納入正式流程的事項；已解決問題請移至 `docs/resolved_issues/<主題>/`。
- 長期 SOP 或常見問題請遷移至 `docs/qa-notes/` 或相關正式文件。
- **按主題歸檔**：將相關問題集中於同一主題目錄，避免分散或混雜。

## 5. 聯動關係

- `AGENTS.md`：定義暫存紀錄與歸檔的高層操作原則，需與本文件同步更新。
- `docs/agent-protected-files.md`：列出暫存紀錄檔案的保護規則，若新增例外或流程變更須同步調整。
- `docs/resolved_issues/README.md`：已解決問題的總索引，結案時需更新。
- `docs/temporary_issues/README.md`：進行中問題的索引，結案時需移除對應條目。
