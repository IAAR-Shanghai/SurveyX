## 📝 如何建立問題記錄

### 建立時機

當遇到以下情況時，應建立暫存問題記錄：

- 🔍 問題需要進一步調查或等待資源
- 🔄 多階段任務需要分批完成
- 🤝 需要使用者確認或其他代理協助
- ⏱️ 長時間運算或部署流程需追蹤

### 檔名規範

```
YYYYMMDD_<簡短主題>.md
```

**範例**:
- `20251017_pdf_conversion_error.md`
- `20251018_model_fine_tuning.md`
- `20251019_api_rate_limit.md`

### 內容模板

```markdown
# <問題簡述>

**建立日期**: YYYY-MM-DD  
**狀態**: 進行中 / 待觀察 / 阻塞中  
**優先級**: 高 / 中 / 低

---

## 背景

- 問題來源與觸發情境
- 涉及的模組 / 任務 / 輸出路徑

## 目前狀態

- 已完成的步驟

## 已嘗試的方法

- 指令、程式碼片段或檢查項目

- [ ] 下一步行動（按優先順序）
- [ ] 需詢問使用者的問題
- [ ] 需等待的條件或資源

## 參考資料

- 相關文件或連結
- 類似問題的解決方案
```

## 🔄 更新問題記錄

### 追加進展

使用時間戳記段落記錄新進展：

```markdown
## 更新 - 2025-10-17 15:30

**操作**: 描述執行的操作
**結果**: 觀察到的結果
**下一步**: 調整後的計畫
```

### 狀態標記

- 🔄 **進行中**: 正在積極處理
- ⏸️ **待觀察**: 已採取行動，等待結果
- ⚠️ **阻塞中**: 受限於外部因素
- ✅ **已解決**: 準備歸檔

## ✅ 結案與歸檔

### 結案條件

問題符合以下條件時應結案：

- ✅ 問題已完全解決
- ✅ 解決方案已驗證
- ✅ 不再需要持續追蹤

### 歸檔流程

1. **在檔案末段新增「結案紀錄」**:
   ```markdown
   ## 結案紀錄
   
   **解決日期**: YYYY-MM-DD
   **解決方案**: 簡述關鍵做法
   **驗證結果**: 確認問題已解決
   **後續監控**: 是否需要觀察
   ```

2. **選擇歸檔方式**:
   - **移轉**: 移至 `docs/resolved_issues/<主題>/`
   - **整合**: 併入既有主題的文件
   - **清理**: 若純屬臨時資訊可刪除（需說明）

3. **更新索引**:
   - 從本檔案移除該問題條目
   - 在 `docs/resolved_issues/README.md` 新增記錄

4. **回報使用者**:
   - 說明歸檔路徑
   - 附上關鍵解決方案
   - 確認是否需要保留特定內容

## ⚠️ 注意事項

### 避免的情況

- ❌ 堆積已解決的問題（應立即歸檔）
- ❌ 混雜不同主題的問題（應按主題分類）
- ❌ 缺乏時間戳記（難以追蹤進展）
- ❌ 過於簡略（缺乏重現資訊）

### 最佳實踐

- ✅ 保持目錄精簡（理想狀態：0-3 個進行中問題）
- ✅ 定期檢視（每週確認是否仍需追蹤）
- ✅ 清楚標註狀態與優先級
- ✅ 提供可重現的資訊與路徑
